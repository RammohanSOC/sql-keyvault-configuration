SQL + Key Vault Encryption (TDE with CMK)

Customer-managed key encryption for Azure SQL using Key Vault, Managed Identity, and RBAC. Used in banking, healthcare, and government.

Azure SQL Server
▶
TDE
▶
Key Vault (CMK)
Ingredients — Prerequisites
✓ Resource Group exists
✓ Key Vault created
✗ Do NOT use MySQL Arc — use Azure SQL only
1
Create Azure SQL Server + Database
SQL
▶
Azure Portal › Search: SQL databases › + Create
FieldValue
DB Namesqldb-demo
ServerCreate new → my-sql-server
RegionSame as Key Vault
AuthSQL + Password
Click Review + Create → Create to deploy both the server and the database.
2
Prepare Key Vault — Enable Required Settings
Key Vault
▶
Key Vault › kv-admin-demo › Settings → Properties
Very important: Both settings below must be enabled before creating the key. They cannot be disabled once on.
SettingRequired State
Soft DeleteON ✓
Purge ProtectionON ✓
Click Save before proceeding.
3
Create Encryption Key
Key Vault
▶
Key Vault › Keys › + Generate/Import
FieldValue
Namesql-key
TypeRSA
Size2048
Click Create. The key will appear in the keys list — note the key identifier URI for reference.
4
Enable System-Assigned Managed Identity on SQL Server
Identity
▶
SQL Server › my-sql-server › Identity

The SQL Server needs an identity so Azure can grant it access to Key Vault. System-assigned identity is tied to this server's lifecycle.

SettingAction
System assignedToggle → ON
Click Save. An Object ID will appear — this is the identity used in the next step.
5
Grant Key Vault Permission to SQL Server via RBAC
IAM
▶
Key Vault › Access control (IAM) › + Add role assignment
SettingValue
RoleKey Vault Crypto Service Encryption User
Assign access toManaged identity
Selectmy-sql-server
RBAC propagation delay: After saving, wait 2–5 minutes before proceeding to step 6. Role assignments are not instant.
6
Configure TDE — Customer-Managed Key
TDE
▶
SQL Server › Security › Transparent Data Encryption
SettingSelection
Encryption typeCustomer-managed key
Key Vaultkv-admin-demo
Keysql-key
Click Save. Azure will now use your Key Vault key to wrap the Database Encryption Key (DEK).
7
Verify the Setup
Done
▶
SQL Server › Security › Transparent Data Encryption
Expected result
✓ Encryption type: Customer-managed key
✓ Key Vault: kv-admin-demo
✓ Key: sql-key

If the TDE page shows "Customer-managed key" and the key reference matches, your SQL data at rest is now protected by your Key Vault key. You own the encryption.

Security best practices

Use RBAC, not access policies
Rotate keys regularly
Restrict Key Vault network access
Enable logging via Azure Monitor
