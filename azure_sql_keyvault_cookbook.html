Quick summary of the flow: The architecture chains three Azure services together: SQL Server holds your data, TDE (Transparent Data Encryption) encrypts it at rest, and your Key Vault holds the master key that controls everything. The critical insight is that you — not Microsoft — own that key. The setup order matters because of dependencies. You can't grant Key Vault access to an identity that doesn't exist yet, and you can't configure TDE with a key the server can't access. So the sequence is: create the SQL server → enable Soft Delete + Purge Protection → create the key → give the server an identity → grant that identity the RBAC role → wire TDE to the key. The two most common failure points are forgetting to toggle on Managed Identity (step 4) before going to IAM, and not waiting the 2–5 minutes for RBAC to propagate before configuring TDE (step 6).
